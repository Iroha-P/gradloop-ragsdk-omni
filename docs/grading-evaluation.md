# 批改评测与双评分策略

## 目标

确定性规则稳定、便宜、可解释，但容易被长度和关键词欺骗；LLM 能理解内容质量，却可能漂移、篡改量表或输出无效结构。当前策略不是简单平均两种分数，而是让确定性评分负责业务决策，让本地 LLM 做可拒绝的旁路复核。

## 执行链路

```text
用户答案
  -> 隐私脱敏
  -> deterministic_multidimensional_v1
  -> 错题与计划决策
  -> 本地 Qwen 严格 JSON 复核
  -> Pydantic 量表校验
     -> 合法：记录分数、分差、置信度和建议
     -> 非法：最多重试一次
        -> 仍非法：拒绝 LLM 结果，保留 baseline
```

LLM 只提交 `criterion_id`、`score` 和简短证据；维度名称和最高分由代码根据原量表补全，防止模型修改评分规则。用户答案被视为不可信数据，提示词明确禁止执行答案中的指令。

## 公开困难合成集

`data/public_eval/grading_cases.jsonl` 包含 10 条合成答案，覆盖：

- 简短空泛；
- 有结构但无证据；
- 堆关键词骗规则；
- 长而流畅但内容空洞；
- 使用无依据数字；
- 结构完整且包含证据、局限和改进。

参考分数是用于开发回归的合成标签，不是多名专家独立标注，不能解释为真实用户评分准确率。

## 当前实测

固定配置：`Qwen3 4B Q4`、llama.cpp、本机运行、temperature `0.1`、每题最多 2 次输出尝试。

| 指标 | 确定性 baseline | Qwen 旁路复核 |
| --- | ---: | ---: |
| 样例数 | 10 | 10 |
| MAE | 22.7 | 9.0 |
| 平均有符号误差 | -7.1 | -6.8 |
| 误差不超过 10 分 | 0.1 | 0.7 |
| 分档一致率 | 0.4 | 1.0 |
| 合法结构覆盖率 | 1.0 | 1.0 |

规则评分把“堆关键词”和“长而空泛”两条困难答案都打到 75 分，暴露了明显的关键词投机问题。本轮 Qwen 能将它们降到 30 分和 40 分，但对极短答案仍可能过度扣分，对强答案也存在偏差。因此当前只将 LLM 作为旁路复核，不直接改变学习状态。

## 下一步校准

1. 建立不少于 50 条脱敏答案，覆盖技术题、项目题、自我介绍和压力面。
2. 至少两名标注者独立评分，先计算一致性，再生成参考标签。
3. 分离开发集与测试集，只在开发集调整提示词、温度和融合策略。
4. 比较确定性、LLM、规则触发复核和加权融合四种策略。
5. 只有测试集稳定且漂移可控后，才允许 LLM 参与错题阈值与计划决策。

## 脱敏双盲人工评分 v3（2026-07-26）

为避免把私人题库或个人项目故事发给协助者，当前 v3 使用 30 条完全重新编写的公开合成评分项目，覆盖自我介绍与故事、项目科研、专业解释、英文表达、压力追问、申请决策六类场景。

答案强度固定为 weak / partial / strong 各 10 条，但外发页面不显示强弱标签、规则分或模型分。评分者只根据问题、候选回答、参考要点和统一锚点填写：

- 清晰度：0–15；
- 覆盖度：0–30；
- 推理：0–20；
- 证据：0–20；
- 反思：0–15。

每个维度已加入 `完全缺失 / 低档 / 中档 / 良好 / 优秀` 五档专属行为锚点。评分者先选择最符合回答表现的档位，再在对应区间内微调整数分；页面会随滑块、加减按钮或档位按钮实时显示当前档位和完整行为描述。“尚未评分”继续使用 `null` 表示，评分者主动选择 `0` 会进入“完全缺失”并计为已完成。行为锚点用于约束评分语义，不把参考观察点变成唯一标准答案。

最终评分包位于 `dist/anonymized-baoyan-human-grading-v3/`，旧 v2 外发 CSV 已停止分发并清理。评分者 A 与 B 分别使用对应的单文件离线 HTML 页面，必须独立填写、不查看对方结果；全部完成后导出的首次 CSV 保持只读，争议讨论不能覆盖原始分数。

两名真实评分者已独立完成全部 30 条五维评分，正式 evaluator 生成的 canonical 状态为 `completed`。聚合结果为总分 MAE `19.3333`、10 分以内比例 `0.2667`、三档一致率 `0.6000`、Cohen's Kappa `0.3182`、quadratic weighted Kappa `0.5645` 和 Pearson correlation `0.7331`。该结果量化的是人工量表一致性与评分尺度偏移，不是模型回答质量或 RAG/Agent 效果提升。

正式评分器只接受项目内 canonical `manifest.json`，并分别校验独立固定的 `items.jsonl` 与 manifest SHA-256；重新生成一个内部自洽的替代 manifest 不能为替代数据集自授权。测试数据必须显式使用 `--fixture-mode`，且 fixture 模式禁止写入 canonical 状态报告。

每两份评分文件都会按直接路径、解析路径、符号链接和硬链接进行文件身份检查，同一底层文件不能冒充两名评分者。`completed` 状态同时记录实际使用的 items 与 manifest SHA-256，使汇总指标能够回溯到唯一数据集；原始评分文件始终保持不变。
